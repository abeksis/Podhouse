      Addresses

      Network storage

      A library on a NAS must be mounted on this box before apps can use it — a container cannot mount a network share by itself. Podhouse writes a systemd automount instead of an fstab line, so an app never starts against an empty folder and decides its library is gone. Once mounted, set Configuration → Media to it.

      Open ports

      Every port this box listens on and the app behind it. All of these are reachable from your network.

      PortAppContainer

      Archives

      A folder on another disk, or on a NAS share already mounted on this box. Leave it empty to keep backups on this box only.

      Encryption key

      Archives are encrypted with AES-256-GCM using this key, because they include .env with every generated password. Without the key an archive cannot be opened. Store a copy away from this machine.

      Automatic backups

      A scheduled backup is always a settings backup. A media library is too big to copy on a timer, and a job that never finishes is worse than none.

      Put a backup back

      Pick an archive and Podhouse opens it, checks it, and shows exactly what it would write over — app by app. Nothing is touched until you confirm, and a fresh backup of the box as it is now is taken first.

      Dashboard password

      The password for this page. Changing it signs out every other device that is signed in.

      Forgot it? There is no email reset. On the server run sudo rm /opt/podhouse/state/auth.json, then homebox bootstrap-token, and set a new one.

      Generated passwords

      Created once by install.sh in .env (mode 600) and never changed afterwards — a key that changes makes stored data unreadable.

      Each value stays hidden until you ask for it, so this page can be shown or shared without leaking them all. From a shell:

      homebox secrets <module>
      NameUsed byValue

      Settings that are not passwords — user IDs, addresses, a game server’s difficulty — are not listed here. They live in Configuration.
